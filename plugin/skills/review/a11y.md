# Accessibility checklist (on demand)

- **Keyboard**: every interactive element reachable by Tab in a logical order; focus visible; custom widgets handle Enter, Space and Escape; no keyboard traps; modals trap focus while open and return it on close; a skip-to-content link.
- **Screen readers**: images have alt text (`alt=""` if decorative); every input has a label; buttons and links have descriptive text; icon-only buttons have `aria-label`; one `<h1>` and no skipped heading levels; dynamic changes announced with `aria-live`; tables have `<th>` with scope.
- **Semantics**: native elements first (`<button>`, not a clickable `<div>`); ARIA only to fill gaps; links navigate, buttons act.
- **Visual**: text contrast at least 4.5:1 (3:1 for large text); UI components 3:1; colour never the only signal; works at 200% zoom; nothing flashes more than 3 times a second.
- **Forms**: visible labels; required fields marked without relying on colour; errors specific, tied to the field and summarised on submit; `autocomplete` on known fields.
- **Content**: `lang` on `<html>`; descriptive `<title>`; touch targets at least 24 by 24 CSS px; meaningful empty states.
- **Test**: keyboard-only pass, an automated checker (axe, Lighthouse), and one screen-reader pass on the changed flow.
